Загрузка второго и следующих проектов

Для новичков: новый проект — новый репозиторий

Не заходи в старый репозиторий и не загружай туда файлы второго приложения. Создай отдельный репозиторий.

В GitHub нажми значок + в верхней панели → New repository. На телефоне открой меню GitHub или страницу github.com/new.

github.com/new
Create a new repository
Owner　tdbuser
Repository name　my-second-project
Visibility　Public
Initialize README　по необходимости
Create repository

Заполни:

  • Repository name — короткое имя латиницей, без пробелов, например my-second-project.
  • Description — необязательно, краткое описание.
  • Public — обычно выбирай для бесплатной публикации GitHub Pages.
  • Add a README file — удобно включить, чтобы репозиторий не был пустым.

Нажми Create repository. В новом репозитории загрузи файлы второго приложения через Add file → Upload files → Commit changes.

Потом включи Pages: Settings → Pages → Deploy from a branch → ветка main → папка /(root) → Save.

Адрес второго сайта: https://tdbuser.github.io/my-second-project/
Вместо my-second-project будет точное имя твоего нового репозитория. Для каждого нового проекта адрес строится по этому же правилу.
Если новый репозиторий создан пустым, сначала добавь в него файлы сайта, включая index.html в корне, и только потом проверяй публикацию.

Как переключаться между проектами

Есть два разных перехода — внутри GitHub и между опубликованными сайтами

А. Перейти к другому проекту внутри GitHub

Нажми логотип GitHub или меню аккаунта → Your repositories. Откроется список репозиториев. Выбери нужный проект по имени.

Прямой список: github.com/tdbuser?tab=repositories.

Б. Перейти с одного сайта на другой

У каждого проекта свой опубликованный адрес. Сохрани адреса в закладки браузера или сделай отдельную страницу-портал с карточками-ссылками на проекты.

Полные основные настройки проекта

Что проверить в Settings перед запуском
Раздел / полеЧто делать новичку
General → Repository nameПроверить имя. Не переименовывать после публикации без необходимости: адрес сайта изменится.
General → Default branchОставить main, если именно эта ветка используется.
General → FeaturesREADME, Issues и другие функции включать только по необходимости.

Pages → Build and deploymentДля нашего простого сайта: Deploy from a branch / main / /(root).
Pages → Custom domainЗаполнять только если подключаешь свой домен именно к этому репозиторию.
Pages → Enforce HTTPSВключить после того, как DNS настроен и GitHub выдал сертификат.

Не меняй настройки Security, Rules, Deploy keys, Secrets и Permissions «на всякий случай». Они не нужны для обычной загрузки статического сайта и могут повлиять на доступ или публикацию.

Как обновить уже существующий проект: открой именно его репозиторий → Add file → Upload files → загрузи изменённые файлы → Commit changes. Затем проверь Actions и сайт. Если обновляешь PWA, на телефоне иногда требуется обновить страницу или очистить старую версию из кэша.

Замена иконки приложения

Повторяем именно тот способ, который использовали для PWA

Для нашего MILLIONER AI MENTOR мы использовали файл icon-512.PNG. Важно, чтобы это была квадратная PNG-иконка размером 512 × 512 пикселей.

Шаг 1. В репозитории открой Add file → Upload files и загрузи icon-512.PNG в корень репозитория — рядом с index.html.

Шаг 2. Открой файл manifest.webmanifest → нажми значок карандаша Edit. В секции icons укажи путь и параметры иконки. Пример:

"icons": [{
  "src": "icon-512.PNG",
  "sizes": "512x512",
  "type": "image/png"
}]

Если в manifest уже есть другие необходимые записи, не стирай их — замени только старую запись иконки или добавь нужную запись в существующий массив.

Шаг 3. Открой index.html → Edit. Внутри секции <head> добавь:

<link rel="apple-touch-icon" href="icon-512.PNG">

Шаг 4. Сохрани изменения через Commit changes. Мы ранее удаляли старый файл иконки с длинным именем 8281E687-C4B6-44C4-AA3...; удаляй старый файл только если проверил, что новый уже загружен и код ссылается на новый.

Подключение собственного домена MILLIONER.UZ

GitHub Pages + DNS у регистратора домена
Важно перед началом: домен MILLIONER.UZ должен вести на отдельный репозиторий сайта MILLIONER.UZ, а не на репозиторий MILLIONER AI MENTOR. Сначала убедись, что открыт правильный репозиторий премиального сайта. Подключение домена меняет адрес, по которому посетители открывают сайт.

Этап 1 — добавить домен в GitHub. Открой репозиторий именно сайта MILLIONER.UZ → Settings → Pages. В поле Custom domain введи:

millioner.uz

Нажми Save. Для публикации из ветки GitHub обычно создаст файл CNAME в корне репозитория.

Этап 2 — DNS у регистратора домена. Открой панель управления там, где куплен/обслуживается домен MILLIONER.UZ. Найди раздел DNS management / DNS records / Zone editor. Для корневого домена добавь четыре записи типа A:

TypeName / HostValue / Points to
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153

Для варианта www.millioner.uz добавь CNAME:

TypeName / HostValue / Points to
CNAMEwwwtdbuser.github.io

У CNAME не добавляй имя репозитория. Для корневого домена используй A-записи. Если у регистратора уже есть конфликтующие записи для @ или www, не добавляй дубли вслепую — сначала проверь старые записи. Не меняй NS/nameservers, если не понимаешь последствий.

Этап 3 — дождаться проверки. Вернись в GitHub → Settings → Pages. Если DNS распознан, GitHub покажет, что домен настроен. Включи Enforce HTTPS, когда опция станет доступна. DNS-обновление может занять до 24 часов.

Ожидаемый результат:
https://millioner.uz — основной адрес сайта MILLIONER.UZ.
https://www.millioner.uz — вариант с www, если DNS настроен; GitHub Pages может настроить перенаправление между ними.
Безопасность: GitHub рекомендует сначала подтвердить право владения доменом в настройках аккаунта, затем добавлять домен в Pages и настраивать DNS. Не создавай wildcard-записи вида *. Не отключай текущий сайт и не меняй DNS до проверки, что выбран правильный репозиторий.

Дополнительные проекты: оставляй их на отдельных адресах github.io, пока не решим назначить им отдельные поддомены. Например, mentor.millioner.uz можно настроить отдельно через CNAME, но это отдельная DNS-операция и отдельная запись Custom domain в репозитории этого проекта.

Если не получается — что проверить

Не нажимай наугад: найди симптом
Что видишьЧто проверить
404 — сайт не найденЕсть ли index.html в корне; включён ли Pages; правильная ли ветка и папка.
Actions красный крестОткрой ошибочный запуск и посмотри сообщение. Не удаляй файлы наугад.
Сайт старый, не обновилсяПроверь, что Commit changes завершился; обнови страницу; подожди публикацию; проверь кэш.
Иконка стараяПроверь имя файла, путь в manifest, apple-touch-icon и кэш/ярлык телефона.
Custom domain не работаетПроверь A и CNAME записи, правильный репозиторий, CNAME-файл, время распространения DNS.
Не вижу SettingsНа мобильном нажми More; убедись, что ты открыл репозиторий, а не опубликованный сайт.
Правило помощи: если запутался, сделай скриншот всего экрана, чтобы были видны адрес страницы и кнопки. Пришли его сюда. Я назову ровно одну следующую кнопку и объясню, что должно появиться.
Контрольный маршрут запуска нового приложения Создать отдельный Repository → загрузить файлы → Commit changes → Settings → Pages → Deploy from a branch → main → /(root) → Save → Actions (зелёная галочка) → Visit site → при необходимости настроить иконку → при необходимости Custom domain + DNS.
Что ещё нужно уточнить для точной инструкции по твоему домену Сама схема DNS выше официальная для GitHub Pages. Но названия полей и расположение кнопок отличаются у регистраторов. Чтобы сделать следующий фотоурок уже с точными экранами именно твоего провайдера домена, понадобится знать, где зарегистрирован MILLIONER.UZ (название сайта/компании регистратора). До этого не меняй DNS-записи.
